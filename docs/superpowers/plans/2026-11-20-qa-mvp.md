# QA MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second analyst can run a complete QA round on a test pipeline: see what needs review, record verdicts, gate a merge with `qa_check()` and produce a PDF report, with the editor showing blocks, maps and QA status.

**Architecture:** A static source model (`read_source()`) parses `R/*.R` and `_targets.R` into reviewable items with token hashes; nothing is loaded or run. A git layer adds authorship. A ledger of one-JSON-file-per-verdict in `qa/reviews/` is combined with the source model into a status table that drives `qa_check()`, `qa_report()` and the editor overlay.

**Tech Stack:** R (>= 4.1), base `tools`/`utils`, jsonlite, roxygen2, targets, withr; git CLI; Quarto CLI with Typst; vanilla JS in `inst/app/index.html`.

**Spec:** `docs/superpowers/specs/2026-11-20-qa-reviews-design.md` (the section "Decisions after the builder check" overrides earlier sections).

## Global Constraints

- Imports stay: jsonlite, roxygen2, targets, withr (+ base tools, utils). No new Imports. `rmarkdown`, `tarchetypes`, `testthat` stay in Suggests.
- The QA engine never loads or runs pipeline code; hashes and status come from parsing source files only.
- Hash = MD5 of the item's parse tokens without comments and whitespace (from `getParseData()`).
- Item ids: `function:<name>`, `target:<name>`, `map:<template names joined by "+">`, `object:<file>:<name>`, `file:<path>`.
- Review entries: one JSON file per verdict in `qa/reviews/`, never edited after writing.
- Verdicts: `"correct"`, `"questionable"`, `"wrong"`; comment required for the last two.
- Identity matched by git email; optional `qa/people` maps several emails to one person.
- Reports without signatures say exactly: "This report was generated digitally and is valid without signature."
- Draft reports carry "DRAFT – QA incomplete"; `qa_report(final = TRUE)` refuses unless `qa_check()` passes.
- Git via `system2("git", ...)`, Quarto via `system2("quarto", ...)`; each feature errors clearly when its tool is missing.
- `inst/app/index.html` stays an HTML fragment; CSS state classes (`.sel`, `.dim`, `.hl`, `.drop`) never reused for form controls; no Google Fonts.
- `devtools::test()` and `devtools::check()` clean at the end of every task.

## Review Focus

1. A function defined twice across files (or redefined in `_targets.R`): ids collide. Expected: `read_source()` errors naming both locations rather than silently keeping one. Test in Task 1.
2. A source file with a syntax error. Expected: `qa_status()`/`qa_check()` fail with the file name and parse message, never a cryptic error. Test in Task 1.
3. `qa_review()` with a name matching several items (function `clean_cs` and target `clean_cs`). Expected: error listing the full ids to choose from. Test in Task 4.
4. A repository without any commit, or a project not in git at all. Expected: `qa_status()` works with `last_author = NA`; `qa_review()` refuses with "commit first". Test in Task 3/4.
5. Renaming a function. Expected: old item disappears, new item is `unreviewed` (no crash on dangling review entries; they are ignored and reported as "orphaned" in `qa_status(orphans = TRUE)`). Test in Task 5.

### Task 1: Static source model

**Files:**
- Create: `R/source_model.R`
- Test: `tests/testthat/test-source_model.R`, fixtures written inline with `withr::local_tempdir()`

**Interfaces:**
- Produces: `read_source(path = ".") -> list(items = data.frame, files = character)`. `items` columns: `id` (chr), `kind` (chr: function/target/map/object/file), `name` (chr), `file` (chr, relative, e.g. `"R/cohort.R"`), `line1`, `line2` (int), `hash` (chr, 32 hex), `block` (chr, = file), `map` (chr map id or NA, for targets), `fn` (chr, project function a target's command calls, or NA), `calls` (list of chr, project functions a function calls), `title` (chr: roxygen title for functions, `description =` for targets, else NA).
- Produces: `item_hashes(path, files) ` is internal; Task 3 re-uses `read_source_text(texts)` where `texts` is a named list `file -> character lines`, returning the same structure (so git can hash old versions without touching disk).

Rules the tests pin:
- Top-level `name <- function(...)` in `R/*.R` → `function` item spanning the assignment.
- Calls in `TARGET_CALLS <- c("tar_target", "tar_render", "tar_quarto", "tar_combine", "tar_file", "tar_file_read", "tar_force", "tar_change", "tar_age")` found anywhere inside a top-level expression → `target` item; name = `name` argument or first argument.
- `tar_map(...)` → `map` item; its templates = target calls nested in it plus targets of any top-level assignment referenced by a bare symbol argument (in any file). Those targets get `map = <map id>`.
- `tar_render`/`tar_quarto` with an existing path → also a `file` item hashing the file text (MD5 of the raw file).
- Every other top-level expression in `R/*.R` and `_targets.R` that contains no target or map call → `object` item; name = assignment LHS, else `<call name>#<n>` (n = occurrence within the file).

**Files:**

**Interfaces:**
- Produces:

### Task 8: Editor: blocks, maps, QA overlay

**Files:**

**Interfaces:**
