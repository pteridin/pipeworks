# pipeworks

R package: a visual editor for `{targets}` pipelines. `pipeworks()` reads a
project (`read_pipeline()`) and opens `inst/app/index.html` with the model
embedded as JSON. RStudio stays the main editor.

## Model

- **Block** is one file in `R/`: its functions plus a
  `pipeline_<file> <- list(...)` with its targets. `_targets.R` only composes
  the blocks. Blocks are drawn as boxes on the canvas (they replaced the
  roxygen `@family` grouping).
- **Target** comes from `tar_manifest()` / `tar_network()` in the editor
  (`read_pipeline()`). Its `mode` is `function`, `expression` or `factory`
  (tarchetypes, e.g. `tar_render()`). `tar_map()` variants are shown folded
  as one pill.
- **Function** is a top-level definition in `R/`. Its roxygen block is the
  source of truth for titles, `@param` and `@return`. One function can back
  several targets.
- **Arguments** are matched to formals per call (`target_call()`), so an
  argument name can differ from the target passed in it.

## QA reviews

A second analyst reviews the code item by item; verdicts live in the repo.
The QA engine is static: it parses source files and never runs pipeline code.

- **Item** (`read_source()`): ids `function:<name>`, `target:<name>`,
  `map:<templates joined by "+">`, `object:<file>:<name>`, `file:<path>`.
  Hash = MD5 of the parse tokens without comments and whitespace (read as
  UTF-8, locale-independent). Scope: every `.R` below `R/` (recursive, like
  `tar_source()`), `_targets.R`, report sources. Each top-level expression
  holding targets also gets a rest item (`object:<file>:<holder or call#n>`:
  its tokens minus the recognised target/map calls, each counted as one
  placeholder), so deleted targets and unknown factories change it.
  `source()`/`sys.source()`/`tar_source(<other dir>)` are listed as
  `external` and fail `qa_check()`.
- **Ledger** `qa/reviews/*.json`: one file per verdict, never edited. Latest
  entry per item wins. Optional `qa/people` (DCF: `Name`, `Emails`) maps
  emails to one person.
- **Status** (`qa_status()`): `unreviewed`, `changed` (hash differs, also
  after a revert), `correct`/`questionable`/`wrong`, plus the non-failing
  hint `check_again` (a callee changed) and `self_reviewed` (entry's reviewer
  equals its recorded author; compared by stored emails, lower-cased, so
  squash and rebase are safe; `NA` = authorship unknown, which fails).
- **Done** = passes `qa_check()` (`qa_passing()`): used by the editor,
  `print()` and the report alike. `check_again` passes.
- `qa_check()` is the CI gate; `qa_report()` renders a PDF with Quarto/Typst
  (draft unless `qa_check()` passes; `final = TRUE` refuses otherwise). Both
  and `read_pipeline()` use `qa_status(authors = FALSE)`: no history walk.
- `last_authors()` walks the history with bulk `git cat-file` reads; per-file
  parses (`parse_source_file()`) are cached by blob, the cross-file step is
  `resolve_source()`.
- Code: `R/source_model.R` (items, hashes), `R/git.R` (git via `system2`),
  `R/qa_ledger.R` (read/write entries, people), `R/qa.R` (`qa_review()`),
  `R/qa_status.R` (`qa_status()`, `qa_check()`), `R/qa_report.R` +
  `inst/report/qa-report.qmd`.
- Test helpers (`tests/testthat/helper-example.R`): `local_project()`,
  `local_git_repo()`, `commit_as()`, `set_git_user()`, `git_cmd()`,
  `reviewed_repo()`, `read_example()`. `example_project(git = TRUE)` is the
  review scenario (`test-example.R`).

## R code navigation: rairai

The `rairai` MCP server (`.mcp.json`) indexes this package's source without
running it. Reach for its tools first when you need:

- where a symbol is defined or used: `definition`, `references`, `symbols`
- the tests covering a symbol: `tests_for`
- everything needed before renaming or changing a function: `refactor_context`
- package-local signatures: `function_formals`
- help pages of installed packages: `help_search`, `help_page`

Fall back to Grep/Read for non-R files (`inst/app/`, `tools/`, the example's
`.Rmd`).

## Example project

`inst/examples/survey/` is the test fixture and demo. Its quirks are
deliberate (see its `README.md`, "Edge cases"); keep them intact.

## Editor frontend

- Edit `inst/app/index.html`. `mockup/pipeline-editor.html` is generated by
  `Rscript tools/build-demo.R` and is the published demo.
- The template is an HTML fragment (no `<html>`/`<head>`) so the same file
  works as an artifact page; keep it that way.
- State classes on canvas elements (`.sel`, `.dim`, `.hl`, `.drop`) live in
  their own namespace; form controls use `.inp`, `.txt`, `.select`. A shared
  class name once collapsed selected boxes to zero width.
- jsdom smoke tests check logic only; layout bugs need a real browser.
- The editor shows QA status read-only (overlay, progress, diff against
  base); verdicts are still set with `qa_review()` in R.
- Edits in the editor stay in memory: writing back to files and the live
  RStudio connection are the next milestone.

## Checks before handing back

`devtools::test()` and `devtools::check()` both clean. The tests read the
example through `read_pipeline()`, which starts a separate R process, so a
run takes about 15 seconds.
